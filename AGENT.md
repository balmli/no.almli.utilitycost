# AI Agent Guide

## Project Overview
- Homey app that models Norwegian electricity and grid costs with support for spot and fixed price plans.
- TypeScript codebase compiled with `tsc`; key logic lives in `lib/` and `drivers/`.
- App manifest and flow cards are defined in `app.json`, while entrypoint logic is in `app.ts`.

## Environment Setup
- Use Node.js 18.20.8 (current Homey CLI baseline). Manage versions with `nvm` or matching tool.
- Install dependencies with `npm install`. The repo vendors `node_modules/`, but reinstall if packages drift.
- Install the Homey CLI globally (`npm install -g homey`) when validating or running the app.
- Copy any required secrets or test data into `data/` if new fixtures are needed; avoid committing sensitive info.

## Tooling & Commands
- `npm run build`: Compile TypeScript sources to `build/`.
- `npm test`: Run mocha tests via `ts-node` and execute `homey app validate` afterward.
- `npm run lint`: Apply ESLint rules aligned with `eslint-config-athom`.
- Prefer `rg`, `ts-node`, and `eslint --fix` when automating searches or fixes; keep changes minimal and focused.
- Homey CLI: `homey login` to authenticate, `homey app run` for live reload, `homey app install --local` to deploy a compiled build; reference https://apps.developer.homey.app/the-basics/getting-started/homey-cli for full workflow.

## Coding Guidelines
- Follow existing TypeScript patterns and keep Homey capability IDs consistent with `app.json`.
- Place reusable business logic in `lib/`, flow/device behaviour in `drivers/UtilityCostsDevice/`, and API glue in `api.ts`.
- Maintain pure functions for calculations where possible; add unit tests in `tests/` alongside relevant modules.
- Update documentation (`README.md`, `CHANGELOG.md`) whenever behaviour or flows change.
- Avoid modifying localized resources in `locales/` unless you are synchronizing all language variants.

## Project Structure
- `app.ts`: App bootstrap and flow card registration.
- `api.ts`: HTTP endpoints exposed to other Homey apps.
- `drivers/`: Device driver and capability handlers.
- `lib/`: Pricing logic, calculation utilities, and data loaders.
- `data/`: JSON datasets for grid and electricity tariffs.
- `tests/`: Mocha/Chai test suites executed via `ts-node`.
- `assets/`: Icons and imagery used by the app.
- `.homeycompose/app.json`: Source manifest; update the app version and metadata here. The root-level `app.json` is generated by the Homey CLI—never edit it manually.
- `specs/`: Markdown specifications for proposed changes and bug investigations.

## Pull Request Checklist
- [ ] Tests and validation (`npm test`) pass locally (requires Homey CLI).
- [ ] TypeScript compiles cleanly (`npm run build`).
- [ ] Lint issues addressed (`npm run lint`).
- [ ] Changelog entries added or updated.
- [ ] New flows, capabilities, or settings documented in `README.md` and matching manifest changes.

## Release Process
- Bump the version in `package.json` and `.homeycompose/app.json` (Homey CLI will regenerate the root `app.json`).
- Document notable changes in `CHANGELOG.md` (latest entry at the top).
- Run `npm run build` and `npm test` before packaging.
- Use `homey app validate` and `homey app install --local` against a test Homey bridge if applicable.
- Tag releases in git following `v<major.minor.patch>` convention once published.
